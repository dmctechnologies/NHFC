New Harvest Fellowship Church Tanzania --- Website README
Website: https://newharvestfellowshipchurch.tz/
About the project
This repository contains the website for New Harvest Fellowship Church
Tanzania (NHFC), a Christ-centered church based in Chibe, Shinyanga,
Tanzania. The website introduces the church, shares its beliefs and
ministries, publishes teaching resources, and helps visitors connect
with the church or support its community projects.

The live website currently presents information about the church's
mission and vision, leadership, church lessons, ministries, outreach
work, projects, and contact details.
Website goals
- Welcome church members, first-time visitors, ministry partners, and
  missionaries.
- Explain the church's beliefs, mission, and vision.
- Share sermons, Bible lessons, and church updates.
- Introduce ministry activities and community initiatives.
- Make it easy for visitors to contact the church, visit, pray,
  volunteer, or support projects.
- Present accurate, accessible information on mobile and desktop
  devices.

Updating the website
1. Review before editing
1. Inspect the existing repository and identify its framework, entry
   point, shared layout, navigation, and deployment method.
2. Check the live website on desktop and mobile.
3. Make a backup or create a Git branch before substantial changes.
4. Keep existing working routes and features unless a change is
   intentional.
5. Do not assume a particular framework, package manager, database, or
   hosting provider from this README; use the configuration in the
   repository.
2. Content quality
- Use warm, welcoming, Christ-centered language consistent with the
  church's identity.
- Keep paragraphs readable and headings descriptive.
- Check spelling, names, Bible references, dates, ministry schedules,
  contact details, and donation information.
- Ask church leadership to approve doctrinal statements, official
  announcements, fundraising claims, and sensitive stories.
- Obtain permission before publishing identifiable photos,
  testimonies, or personal information---especially information about
  children and vulnerable people.
- Clearly distinguish current activities from planned projects.
- Add publication or update dates to news and teaching content where
  appropriate.
3. Design and usability
- Ensure the site works well on small screens, tablets, and desktop
  displays.
- Use consistent typography, spacing, colors, buttons, and page
  layouts.
- Make the main actions easy to find: learn about the church, read
  lessons, explore ministries, contact the church, and support
  projects.
- Provide descriptive alternative text for meaningful images.
- Use readable contrast, visible keyboard focus, semantic headings,
  and properly labelled forms.
- Compress images and avoid unnecessarily large media files.
- Check that navigation, email links, phone links, social links, and
  external links work.
4. SEO and sharing
- Give every important page a unique, accurate page title and meta
  description.
- Use one clear main heading per page and a logical heading structure.
- Use descriptive URLs and meaningful image filenames where practical.
- Add social-sharing metadata and a suitable preview image.
- Verify the canonical domain, sitemap, robots rules, and favicon.
- Avoid publishing duplicate pages or unsupported claims about the
  church's impact.
Development and deployment
The exact commands depend on the technology used in the repository.
Check the project's configuration files and hosting dashboard before
running commands.
1. Clone or open the repository.
2. Install dependencies using the package manager indicated by the
   lockfile or project documentation.
3. Configure required environment variables using the hosting
   provider's secret/environment-variable settings. Never commit
   passwords, API keys, private credentials, or .env files containing
   secrets.
4. Run the project's documented local development command.
5. Test all changed pages and links locally.
6. Run the available lint, type-check, and build commands.
7. Review the final changes and commit them to version control.
8. Deploy through the project's established hosting workflow.
9. After deployment, test the live site on mobile and desktop,
   including forms, contact links, media, and any donation flow.
Important: Do not copy generic commands into production without
checking the actual project scripts and deployment setup.

Suggested improvement priorities
1. Accuracy: Review old project targets, donation progress,
   ministry schedules, and statistics so visitors can distinguish
   current information from historical information.
2. Clear visitor journey: Make it easy to find service information,
   location, contact details, and ways to get involved.
3. Project transparency: For each fundraising project, show a
   verified goal, latest progress date, intended use of funds, and a
   clear contact or giving process.
4. Stories and updates: Publish dated church news, Bible lessons,
   outreach updates, and approved testimonies.
5. Performance and accessibility: Improve mobile speed, image
   optimization, contrast, keyboard access, and alternative text.
6. Security and maintenance: Keep dependencies updated, protect
   forms and administrative access, back up the website, and document
   how to restore it.
